Vue d'ensemble

Shop App est une application web interne développée pour The SMARTPHONE, boutique de vente et réparation de téléphones au 1 Avenue d'Italie, Paris 13e.

Elle centralise l'ensemble des opérations quotidiennes : caisse, réparations, stock, catalogue, devis, commandes fournisseurs, comptabilité et communication automatisée (email + WhatsApp).

restart.bat — Démarrage serveur

@echo off
taskkill /F /IM node.exe 2>NUL    ← Tue l'ancien processus Node
taskkill /F /IM chrome.exe 2>NUL  ← Tue les Chrome orphelins
cd /d C:\apps\shop-app
node server.js > C:\apps\shop-app\server.log 2>&1

Commandes de déploiement

# Sur le PC de dev :
git add -A
git commit -m "description des changements"
git push origin master

# Via SSH depuis le PC dev :
ssh prod "powershell -Command \"cd C:\\apps\\shop-app; git pull\""
ssh prod "powershell -Command \"schtasks /Run /TN RestartShop\""

Créer la tâche planifiée (une seule fois)

schtasks /Create /TN "RestartShop" /TR "C:\apps\shop-app\restart.bat" /SC ONSTART /RU SYSTEM
ℹ️
La tâche RestartShop se lance automatiquement au démarrage du PC du magasin. Elle peut aussi être déclenchée manuellement via schtasks /Run /TN RestartShop.
⚠️
Toujours exécuter taskkill /F /IM node.exe avant de relancer le serveur, sinon deux instances Node tournent en même temps et la seconde échoue sur le port 3000.

Gmail OAuth2

L'application utilise la Gmail API (pas SMTP) pour envoyer les emails. Cela évite les blocages Google sur les mots de passe d'application et les restrictions de sécurité.

Flux d'autorisation OAuth2

Fig. 4 — Flux d'autorisation Gmail OAuth2

Procédure d'autorisation

#ActionOù
1Aller sur http://100.126.44.43:3000/api/gmail/auth-sendNavigateur
2Copier l'URL affichée et l'ouvrir dans ChromeChrome connecté à smartphonesatelier4@gmail.com
3Cliquer "Autoriser" sur la page GoogleGoogle OAuth
4La page affiche ✅ Gmail autorisé !Redirection /api/gmail/callback
5Les tokens sont sauvegardés automatiquementgmail_tokens.json

Fichiers clés

FichierRôleGit
gmail-send.jsModule partagé d'envoi : lit tokens, construit MIME, envoie via APIVersionné
gmail_tokens.jsonTokens OAuth2 (access + refresh). Renouvelés automatiquement.Ignoré (.gitignore)
client_secret_*.jsonCredentials OAuth2 (Client ID + Secret Google Cloud)Ignoré (.gitignore)
✅
Le refresh_token est permanent. L'access_token expire toutes les heures et est renouvelé automatiquement par gmail-send.js via l'événement oauth2.on('tokens'). Aucune ré-autorisation n'est nécessaire en conditions normales.

WhatsApp

Le PC magasin maintient une session WhatsApp Web permanente via whatsapp-web.js + Puppeteer/Chrome. Cette session est utilisée pour envoyer le rapport comptable quotidien dans le groupe planning ITtech.

Cycle de vie de la connexion

Fig. 5 — Cycle de vie de la connexion WhatsApp

Connexion initiale

#Étape
1Ouvrir http://100.126.44.43:3000/whatsapp-setup.html
2Scanner le QR code avec le téléphone du magasin
3La session est sauvegardée dans .wwebjs_auth/
4Les redémarrages suivants se connectent automatiquement (sans QR)

Problèmes connus et solutions

ProblèmeCauseSolution
Chrome orphelin (nombreux processus) Serveur tué sans arrêt propre → Chrome reste en mémoire restart.bat fait taskkill /F /IM chrome.exe avant relance
WhatsApp bloqué à 99% 25+ processus Chrome en session 2 saturent la RAM Tuer tous les Chrome manuellement, redémarrer proprement
Session déconnectée Téléphone déconnecté WhatsApp Web ou session expirée Re-scanner le QR sur /whatsapp-setup.html
Suppression message impossible message.delete(true) vérifie canSenderRevokeMsg() et supprime silencieusement pour soi seulement Utiliser Cmd.sendRevokeMsgs() via pupPage.evaluate() pour contourner la vérification
🚫
Ne jamais supprimer .wwebjs_auth/ — c'est la session WhatsApp enregistrée. Si supprimé, il faudra re-scanner le QR code avec le téléphone du magasin.

Rapport automatique (20h)

Chaque soir du lundi au samedi à 20h00, le rapport comptable est généré et envoyé automatiquement par email et WhatsApp.

Configuration .env

Le fichier .env à la racine du projet est non versionné (dans .gitignore). Il doit être présent manuellement sur chaque serveur.

# ── Base de données ──────────────────────────
DB_HOST=localhost
DB_PORT=5432
DB_NAME=shop_db
DB_USER=postgres
DB_PASSWORD=Sempac

# ── Gmail OAuth2 ─────────────────────────────
GMAIL_CLIENT_ID=1085866438359-...
GMAIL_CLIENT_SECRET=GOCSPX-...
GMAIL_REDIRECT_URI=http://100.126.44.43:3000/api/gmail/callback

# ── Destinataires rapport ─────────────────────
EMAIL_TO=ittech75013@gmail.com
WA_TO=33XXXXXXXXX@c.us         # ou ID groupe : XXXXXXXXXXX@g.us

# ── Rapport PDF ───────────────────────────────
RAPPORT_DIR=C:\Users\PC\OneDrive\Documents\Rapport Comptable

# ── Serveur ───────────────────────────────────
PORT=3000
🔐
Ne jamais committer le fichier .env, gmail_tokens.json ou client_secret_*.json sur GitHub. Ces fichiers contiennent des credentials sensibles.
